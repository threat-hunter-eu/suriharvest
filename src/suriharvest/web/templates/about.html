What suriharvest does

It downloads free Suricata rulesets, parses every rule, checks that it loads in a real Suricata (suricata -T), merges copies and mirrors into one entry per rule, and builds the rulesets you define as profiles. Nothing leaves your machine except the source downloads.

  1. Sources: tarballs, files and git repositories from sources.yaml
  2. Parse: one entry per rule text; lines that do not parse are quarantined, never dropped silently
  3. suricata -T in every engine of suriharvest.yaml, cached by rule text
  4. Dedupe: identical logic from several sources becomes one rule, with every copy and its licence
  5. Profiles: a search, an engine and your exclusions
  6. Builds: suricata.rules, what changed, what was left out and why

Sids

Suricata loads one rule per gid:sid. Who owns a sid comes from the public allocation table at sidallocation.org: a rule inside a publisher's range is that publisher's rule, wherever it was found (rule key namespace:gid:sid, the newest rev wins between copies).

When two different rules share a sid, the best one keeps it and the others get new sids from remap_base (now {{ remap_base|num }}, outside every allocated range). Every decision is written to state/sid-map.tsv, so a remapped sid never moves between builds: alerts, suppressions and thresholds keep working.

Rules whose sid was remapped: remapped:yes.

Daily work in the browser

  1. Overview → Download new rules: every enabled source, checked in Suricata, every profile rebuilt. Sources → Download only this does it for one source.
  2. Builds & changes → New to review: what a profile would get that is not in its last build. Tick what you do not want and exclude it.
  3. Profiles & exclusions: add by name, or search and tick rules; also in exclusions/<profile>.yaml. Rebuild now applies it.
  4. Export: suricata.rules, one file per source, or a suricata-update URL.

Data and privacy

Everything stays in the workspace: the database, the downloaded rules and the builds. The only network calls are the source downloads (and Docker images for container engines).

This server listens on 127.0.0.1 by default; on another address it asks for a token.

Credits and trademarks
